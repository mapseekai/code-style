# code-style

Go、Rust 与 TypeScript 的中文代码规范，供日常编码、重构、代码审查和 AI 辅助开发使用。以正确性、可读性、一致性和可维护性为共同目标，结合各语言的惯用实践，说明代码组织、接口设计、错误处理及验证方式。

## 规范文档

| 语言 | 文档 | 主要内容 |
| --- | --- | --- |
| Go | [Go Code Style](go-code-style.md) | 包与接口设计、值与指针、错误处理、Context 与并发、资源管理及测试检查 |
| Rust | [Rust Code Style](rust-code-style.md) | 类型与 API、所有权与内存、安全抽象与 unsafe 契约、异步并发及工具检查 |
| TypeScript | [TypeScript Code Style](ts-code-style.md) | 模块与类型设计、数据边界、错误处理、Promise 与取消、资源管理及类型感知检查 |

三份文档均包含格式与命名、文件布局、注释与文档、测试与验证，并附有相关参考资料，便于进一步查阅规则依据。

## 如何使用

先按当前语言选择文档，再结合项目及组件约定，确认适用的工具链版本、运行环境、接口契约和检查命令。多语言项目分别采用对应规范，并保持跨组件的数据与错误语义一致。

- **编码**：在设计类型、接口和模块边界时参考相关章节，沿用语言惯用写法与项目已有约定。
- **重构**：围绕具体问题调整结构，在保持行为与接口契约的前提下改善可读性，并验证受影响的路径。
- **代码审查**：结合变更范围检查正确性、错误传播、并发与资源归属，再核对命名、布局和文档的一致性。
- **AI 辅助开发**：将对应规范与项目说明、任务范围一并提供给助手，要求其按适用条款实现或审查，并报告实际完成的验证。

例如，处理 Rust 任务时可以这样说明：

> 请阅读 rust-code-style.md 和当前项目、组件的约定，按本次任务范围完成修改。遵守安全契约，对工程偏好的取舍说明理由，并报告相关检查的实际结果。

## 规则的取舍

涉及内存安全、数据边界、权限保护、并发正确性和资源生命周期的要求，应结合具体契约落实。对这些要求的判断以实际行为和安全前提为依据。

“必须／不得”表示硬性约束；“优先／避免”表示默认建议。命名、布局和抽象方式等工程偏好可结合项目需求权衡，保持同一范围内的一致性，并说明必要例外的原因。

格式与静态检查采用项目配置的工具，测试覆盖实际行为和重要边界。各文档的“工具与检查”章节提供相应语言的执行参考，使用时按项目结构与环境选择适用命令。
